# Gotchas

Traps, quirks, and things not to change without care.

---

## Never edit `graphql/generated.go` or `sqlc/db/` directly

These files are auto-generated by `gqlgen` and `sqlc` respectively. Manual edits will be overwritten on the next `make gqlgen` or `make sqlc`. Always make changes to the source files (`.graphqls` schema or `sqlc/query.sql`) and regenerate.

---

## Schema changes require resolver stub updates

When you add a new field or type to a `.graphqls` schema file and run `make gqlgen`, gqlgen updates `generated.go` but may add new resolver method stubs to `*.resolvers.go`. Check the generated resolver files for `// TODO: implement` stubs after every schema change — unimplemented resolvers panic at runtime.

---

## `@auth` directive must be applied to new protected fields

New query/mutation fields that require authentication must have `@auth` in the schema. Forgetting this means the field is publicly accessible. The directive check in `server.go` enforces this — but only for fields that have it declared.

---

## JWT user ID is in the request context, not the resolver parameters

Resolvers get the authenticated user's ID from `reqctx.GetValue(ctx).UserID` — not from query arguments. Never accept a user ID from the client for operations on behalf of the caller; always use the context value to prevent horizontal privilege escalation.

---

## `decimal.Decimal` must be used for all monetary values

Do not use `float64` for expense amounts anywhere in the codebase. Even for display or intermediate calculations, use `decimal.Decimal`. Float precision errors in financial calculations cause incorrect balance settlements.

---

## Migrations run automatically in Docker Compose but not locally

The `migrate` Docker Compose service applies migrations on startup. When running `make run_local`, migrations must be applied manually (or by running the migrate service separately). Check `migrations/` for pending migrations after a `git pull`.

---

## Soft-deleted records must be excluded in every query

All queries against soft-deleteable tables (expenses, groups) must include `AND is_deleted = false`. SQLC functions generated from `sqlc/query.sql` include this filter — do not bypass them with raw SQL.

---

## Rate limiting config is a separate file

`ratelimit.yaml` configures per-operation token bucket limits. Changing it requires a server restart (it is loaded at startup). Do not hardcode rate limit values in Go code.

---

## `gqlgen.yml` controls which types are auto-generated vs. manually defined

The `gqlgen.yml` file maps some types to existing Go types (e.g., `Decimal` → `shopspring/decimal.Decimal`) and prevents others from being regenerated. If you add a new custom scalar or model, update `gqlgen.yml` before running `make gqlgen`, or the generator will create a conflicting type.

---

## pg_advisory_lock requires a pinned connection

`pg_advisory_lock` and `pg_advisory_unlock` must execute on the same PostgreSQL session. With `pgxpool`, connections are returned to the pool between calls. Always acquire a dedicated `pgxpool.Conn` before calling the lock, and release it (via `defer conn.Release()`) only after the unlock runs. Defer order matters: unlock must run before `conn.Release()` — LIFO means unlock should be deferred second.

---

## Source legs must be included in balance, excluded from display

The `Expenses` resolver fetches all DB expenses first, computes balance from that full set, then builds the display list skipping source legs (`GetSourceExpenseIdsForGroup`). Never compute balance from the filtered display slice — source legs cancel the old-currency debt and their absence produces wrong balances.

---

## Deleting a Conversion target cascades; deleting a source leg is blocked

`DeleteExpense` on a `Conversion`-type expense soft-deletes both the target and its linked source leg atomically inside a transaction (`SoftDeleteConversionLegs`). If the expense is a `Repayment` that is a source leg (found via `GetConversionBySourceExpenseId`), deletion is blocked with `ConversionSourceLegDeletion` error.

---

## Subscription resolver requires a working subscription transport

The `subscription.resolvers.go` implements a real-time expense update subscription. This requires the frontend to use a WebSocket-compatible GraphQL transport. The HTTP-only `query<T>()` wrapper in the Dutch frontend does not support subscriptions.
